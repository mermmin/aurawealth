## 1. What it is
A full-stack personal wealth & subscriptions dashboard. It links mock bank accounts (Plaid sandbox), shows net worth and spending by category, and keeps a ledger of recurring subscriptions. Design story: a calm, editorial personal-finance UI in a light plum-and-blush theme: warm off-white background `#F9F6F3`, deep plum `#512C48` for primary actions and key figures, blush `#F1E3E7` highlight surfaces, pink accent `#C890A5`; condensed serif headlines over a clean sans for numbers, and warm, plain-spoken copy ("A little clarity. A lot of possibility."). Tokens in §9.

**Purpose:** Résumé/portfolio project for Product Engineer and Software Engineer roles. It needs a live link, a clean README, and real tests.

## 2. Final scope

### v1 MVP (this is the whole goal right now)
| Area | What's in |
|---|---|
| **Backend** | Java 17, Spring Boot 4.1, Maven |
| **Database** | PostgreSQL, migrations with **Flyway** |

| **Pages** | Login, Dashboard (net worth + category chart), Accounts, Subscriptions ledger |
| **Design** | Quick Figma mockups of the 3 main pages before building the UI |
| **Testing** | JUnit 5 + Mockito for services; Spring Boot Test for controllers |
| **Local setup** | Docker Compose (Postgres + backend) |
| **CI** | GitHub Actions: build + run tests on every PR |
| **Deploy** | Railway or Render (no AWS for v1) — live clickable link |
| **README** | Live link, build badge, architecture diagram, Figma screenshot, one-command setup |

### v2 (only after v1 is live — do not start early)
1. LLM "Spending Insights" page: monthly summary of spending habits in a dry, witty voice
2. Stripe webhooks (test mode) to update subscriptions automatically
3. Redis cache for the net worth query
4. Picocli Java CLI: `sync` and `networth` commands

### Out of scope
- AWS ECS/EC2/RDS deployment
- Real (non-sandbox) bank data
- Mobile app
- Astrology framing anywhere in the repo or README

## 3. Decisions log
- Flyway, not Liquibase (simpler)
- Railway/Render, not AWS (avoid server/ops work)
- v1 = 4 entities, 4 pages; everything else waits for v2
- Name "AuraWealth" was a working title; confirmed 2026-10-25 that it stays (see below)
- Spring Boot 4.1 instead of 3.x (2026-10-24): start.spring.io no longer offers 3.x and its open-source support has ended. Still Java 17.
- Plaid access tokens encrypted at rest (2026-10-25): AES-256-GCM via a JPA `AttributeConverter`, key from `TOKEN_ENCRYPTION_KEY`. Small extra cost, real protection against DB dumps, reads well in the portfolio. Rotating the key makes stored tokens unreadable (fine for sandbox; users would just re-link).
- Design palette changed (2026-10-25): from the matte-charcoal dark mode to a **light plum-and-blush theme**: background `#F9F6F3`, plum `#512C48`, blush `#F1E3E7`, pink accent `#C890A5`. Light mode only for v1. The product name stays **AuraWealth**; "Bloom" in the Figma file is a placeholder and must not appear in the app or README.
- API gaps from the mockups (2026-10-25): **in v1:** display name and last-synced time (Session 18). **Not in v1:** merchant/bank logos and brand colors (use generic category icons + letter tiles) and fine-grained categories (show friendly labels for Plaid's primary category). Both are possible later from Plaid data (`logo_url`, institution metadata, `personal_finance_category.detailed`).
- `asOf` on net worth is the **oldest** last-sync across the user's banks, not the newest: a total is only as current as its stalest bank (2026-10-25).
- Frontend on **Vite 6**, not 7 (2026-10-26): Vite 7 needs Node 22.12+, the dev machine has 22.8. Tailwind v4 (CSS `@theme` tokens, `@tailwindcss/vite`), React Router 7 for the three routes, lucide-react for icons. Breadcrumb root is "Your money" (not "My workspace") and the user-switcher chevron is dropped: v1 has no workspaces.
- ~~Deploy on **Railway Hobby** (2026-10-27)~~ superseded the same day, see next entry: about $5/month with $5 of usage included; Postgres doesn't expire and the app doesn't sleep, so the portfolio link keeps working. Render free was ruled out: its free Postgres is deleted 30 days after creation (+14-day grace) and free services sleep after 15 idle minutes (~1 min cold start).
- Deploy on **Render free + Neon free** (2026-10-27, replaces Railway): Railway paused new signups after its Oct 21 security incident with no reopening date. Render free web service runs the Docker image (512 MB RAM, sleeps after 15 idle minutes, so the first visit after a quiet spell waits ~1–2 min); Neon free Postgres doesn't expire (0.5–1 GB, compute idles after 5 min and wakes in ~1 s; needs `sslmode=require`). $0/month. Upgrade path if the cold start hurts: Render Starter (~$7/month) with the same Neon database.
- **One service, one origin** (2026-10-27): the Vite build is copied into the Spring Boot jar's `static/` by a multi-stage `Dockerfile`; `SpaController` forwards client routes to `index.html`. No CORS and no API URL setting; the frontend's relative `/api` calls work unchanged.
- JWT kept in **localStorage** until its `expiresAt` (2026-10-26): survives reloads with no refresh-token endpoint; a 401 from any non-auth call signs out and clears the TanStack Query cache. Fine for a sandbox portfolio app; an httpOnly cookie would be the hardening step.
- Subscription "inactive" rule (2026-10-25): inactive once the next expected charge is more than a grace period overdue (weekly 7 days, monthly and annual 30). Replaces "two periods with no charge", which kept a lapsed annual plan active for a year. Ledger sorts active first, then soonest next charge.

## 7. Blockers / open questions
- Setup note: Docker Desktop must be open and running (whale icon in the menu bar) before `docker compose up`, or you'll get a "cannot connect to Docker daemon" error.
- Setup note: the `docker` CLI lives in `~/.docker/bin`; that's now on PATH via `~/.zshrc`. Open a new terminal if `docker` says "command not found".

- Setup note: `./mvnw test` needs Postgres running (`docker compose up -d`); repository tests use the real database, not an in-memory one.
- Editor note: VS Code's SQL Server (mssql) extension flags Postgres syntax in migrations as errors; they're false positives. Edit migrations in `src/main/resources`, never the copy in `target/`.

- Possible later polish: 400 validation responses currently say only "Invalid request content." without naming the bad field; may want field-level errors for the frontend forms (M6).
- Possible later polish: linking the same bank twice creates a second item with duplicate accounts (doubles net worth). Plaid returns the institution id on link; the backend could refuse or replace an existing item for the same institution. Test new links with a fresh user, not user 80.
- Possible later polish: subscription detection ignores refunds, so a merchant whose charges are always refunded (sandbox United Airlines) still shows as a subscription. Could skip merchants whose refunds cancel their charges.
- Design follow-ups for M6 (details in §9): muted text `#827780` fails WCAG AA on small text, use `#6B6269`; "Credit card balance" copy under liabilities is wrong once loans exist; designs need a negative net worth, 14+ accounts, loans, and loading/error states.
- Deploy note: production secrets live only in Render's Environment tab (never in the repo or chat). Rotating `TOKEN_ENCRYPTION_KEY` makes stored Plaid tokens unreadable (users re-link); rotating `JWT_SECRET` signs everyone out. `SPRING_PROFILES_ACTIVE=prod` makes a missing variable stop startup with its name.
- Free-tier cold start: the Render free instance sleeps after 15 idle minutes; the first visit after that waits while the container and Spring Boot start. Possible polish: a "waking up the server" note on the login page, or Render Starter (~$7/month) with the same Neon DB.
